# 流水线长任务与高日志量性能加固设计

## 背景

流水线实时回显虽已限制详情面板的显示行数，但浏览器仍会在执行结束前累计完整
`stdout`/`stderr`；尾窗每次追加还会复制整个 256 KiB 字符串。服务端定时任务使用
`execFile` 全量缓冲，页面运行和服务端计划也没有全局并发上限。另有代理响应事后限额、
历史逐条重序列化和失败归档 Promise 常驻等问题。这些路径在大输出或长时间运行时会放大
堆内存、CPU、I/O 与进程数量，最终表现为页面或服务端“卡死”。

## 设计

1. 浏览器输出改为分片尾窗。每路最多保存 256 KiB，追加只裁掉队首分片；仅在生成 UI
   快照时按修订号惰性拼接。`execStreaming` 不再持有完整分片数组，返回值同样是有界尾窗。
2. 脚本输出变量在流到达时逐行解析，支持跨分片的 `KEY=VALUE`、单行 JSON 和 JSON 路径。
   `*=全文` 只捕获 128 KiB；超过内核单环境变量安全边界后不注入并追加明确警告。完整脚本
   回显仍由 `/exec-stream` 服务端直接写任务日志，浏览器只保存日志路径和尾窗。
3. 轮询型页面任务的内存日志也使用有界分片；Jenkins、HTTP 与 EvalTokens 的完整日志经服务端
   追加接口串行落盘，每轮拉取等待对应写入完成，对归档网络形成背压而不堆积待写 Promise。Jenkins
   控制台同步使用增量输出探针，早期变量离开尾窗后仍可传给下游。
   手动 Prometheus 收集只更新一个有界文本窗口，后台采集强制走流式执行。HTTP 文本响应在浏览器
   直连模式下也边读边执行 20 MiB 限额。HTTP/Jenkins 阶段从进入阶段起建立 deadline，并将同一
   `AbortSignal` 贯穿 crumb、触发、状态轮询和控制台读取，阶段超时或用户中止可立即断开等待。单次 Jenkins
   控制台响应超限后停止本阶段后续拉取，保留 Jenkins 终态并显示日志不完整告警。
   API/定时执行器的最终控制台请求也在同一 deadline 内：超时使阶段失败，其他读取故障则保留构建终态并记录告警。
4. 页面最多同时运行 4 条流水线；无机器冲突但槽位已满时进入原有队列。服务端 API/定时执行
   共用 2 个执行槽位，其余任务排队，避免批量到期时同时创建大量子进程。服务端等待队列最多
   100 条；满载时 API 返回 503，一次性/周期计划保留触发并在下个 tick 重试。
5. 服务端脚本执行改用 `spawn` 流式写任务日志、仅在内存保留 256 KiB 尾窗并增量解析变量；
   汇总日志通过 `/concat-stream` 从各任务日志文件顺序复制并原子替换，不再把完整日志回读浏览器或
   拆行后再次驻留内存。脚本任务日志 writer 从打开到写完终态标记全程持有路径锁，组合汇总按固定
   顺序等待所有源文件锁，确保用户中止时不会在 `[aborted]` 落盘前提前读到 EOF。轮询日志追加请求
   按目标路径串行执行，失败/断开时回滚到本次追加前的文件长度。页面在发起 `exec-stream` 前同步保存预期任务日志路径；
   若用户在服务端建目录/打开文件、但响应头尚未返回时中止，汇总仍使用该路径并等待同一文件锁。
6. `/api/worktable/proxy` 先检查 `Content-Length`，并在每个响应块到达时累计字节数；超过
   20 MiB 立即销毁上游响应并返回 502。
7. 流水线历史存储将配置和各历史记录各序列化一次，通过累计长度确定可保留前缀，避免每删除
   一条旧记录就重建整份 JSON。
8. 归档写任务在 resolve/reject 两条路径都从在途集合移除；失败信息单独以有界、可消费的映射
   保存，使“打开归档目录”仍能报告最近失败而不会永久持有 Promise。
9. 高频流式输出只按 250ms 刷新节奏物化尾窗字符串；Prometheus 手动收集窗口同时限制 256 KiB
   字符和 1000 个 DOM 节点，避免大量细碎 span 形成隐藏的渲染/GC 压力。

## 验证边界

- 小输出的 stdout/stderr、变量传递和归档格式保持兼容。
- 超大页面输出内存状态始终不超过配置尾窗，已淘汰分片不残留引用；完整服务端任务日志仍可读到头尾。
- 并发任务不会超过页面/服务端槽位，完成后自动排空。
- 代理同时覆盖声明长度和 chunked 超限。
- HTTP/Jenkins 超时覆盖首个请求和最终控制台读取，且 AbortSignal 能到达底层 fetch；控制台单块超限不会按原 offset 重复下载，非超时读取失败有可见告警。
- 历史裁剪保留最新记录且 JSON 有效，序列化次数与记录数线性相关。
- 归档失败可报告，且在途集合不残留 rejected Promise；追加中断不破坏既有日志，汇总保留大任务日志头尾和中止终态标记，
  包括建目录/打开日志期间的响应头前中止窗口。
