数据来自 Registry HTTP API（/v2/_catalog 分页 + /v2/<repo>/tags/list），经 DSH 服务端代连（仅回环/内网目标）；删除标签按 digest 删除 manifest，删除后建议到「设置」页执行垃圾回收（garbage-collect）释放磁盘。

添加/改标签与改仓库名都走纯 Registry API、不传输任何镜像数据：加/改标签是「取源标签的 manifest 原文 → PUT 到新标签」（新标签已存在即覆盖）；改仓库名是「对每个 blob 做跨仓 mount（只建引用）→ PUT manifest → 删旧仓 manifest」，因为 blob 存储是内容寻址的全局库，32GB 镜像改名同样是秒级。改名为移动语义：搬完会删掉旧仓库名下的 manifest（磁盘释放仍需 GC）。

提交远程镜像缓存任务

流程：docker pull 源镜像 → docker login 目标仓库 → docker tag → docker push（脚本 registry_cache.sh）。目标仓库地址与账号取「设置」页配置；同一时间只跑一个任务（本机 Docker 串行更稳）。中止会杀掉任务进程组。

超时怎么填：公网镜像站把 blob 转发到境外 CDN，实测只有 3~4 MB/s——一个 9 GB 压缩层的镜像（如 vllm/vllm-openai，解压后 32 GB）光下载就要 40 分钟以上，加解压落盘与 push 常超 1 小时。默认 180 分钟；拿不准就留空（不限时），随时可点「■ 中止」。超时被杀不是白跑：docker 会复用已下载完成的层，重跑即续传。

镜像仓库连接

设置仅保存在本机 localStorage（ir_cfg_v1），不上传服务端；密码仅用于本页经服务端代连时构造 Authorization 头。

仓库已开启 htpasswd 认证（realm lhf private registry，账号 admin）：本页不内置任何密码，首次使用必须在上面填入仓库密码并「保存设置」，否则所有 /v2/ 请求都会 401、列表恒为空。密码见仓库部署机上的 /mnt/images/docker-registry/README.md（与 Web UI 8080 登录口令同一套；换口令用 htpasswd -Bbn 重写 auth/htpasswd 后 docker compose restart registry）。

「远程缓存」的 docker login 由本机 docker daemon 执行（CLI → daemon POST /auth），失败常见三类：① TLS handshake timeout —— 仓库地址填了局域网 IP（如 192.168.1.101:5000）而 daemon 只信任回环：需在 /etc/docker/daemon.json 加 "insecure-registries": ["192.168.1.101:5000"] 并重启 docker（本机用 127.0.0.1:5000 免配置）；② 401 Unauthorized —— 账号/密码与仓库 htpasswd 不一致（仓库账号为 admin）；③ connection refused —— 地址或端口填错 / 仓库未运行。
