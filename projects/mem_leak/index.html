四层定位法

0先分清内存层

working_set = usage − inactive_file，仍会包含活跃页缓存。先拆 anon、file/cache、shmem，避免把 NFS/CUDA 库页和日志缓存当泄漏。

1连续趋势采样

单点 RSS 没有结论价值。先拆 RssAnon/RssFile，再按 PID 与角色看斜率、平台是否抬升以及锯齿是否回落。

2进程与资源归因

按 side/role/PID 记录 anon、file、pin、线程和 fd；pod 重建或卡位对调时依靠进程名重新发现。

3轻量代码归因

在线先做 smaps 分桶与 py-spy 单快照。只有确认无 JE 心跳看门狗且有维护窗口，才考虑中侵入工具。

cgroup v1 分解
CG=/sys/fs/cgroup/memory/kubepods/burstable/pod<UID>/<容器ID>
grep -E '^(active|inactive)_(anon|file)|^cache|^shmem' "$CG/memory.stat"
本环境 pod 级 memory.stat 不聚合子容器，必须遍历 pod<uid>/*/memory.stat 求和；pod 级 memory.usage_in_bytes 才是聚合值。cache 与 active/inactive file 等字段存在总量/子项关系，不可直接相加。
不要在承载流量的容器执行 memory.force_empty。它会对目标 cgroup 触发强制回收并尽可能回收页面，不是“只清 page cache”的只读诊断开关。确需验证回收性时，只能在摘流或隔离副本的维护窗口由值班负责人受控执行；参见 Linux 内核 cgroup v1 文档。
组成解释判定
anon进程堆/匿名页持续涨才指向真泄漏
file/cacheNFS 模型、CUDA 惰性加载库页、日志页缓存通常可回收；结合 dirty/writeback 与压力下回落确认
shmemRay plasma、NCCL/TENT 握手段持续涨指向共享内存泄漏
VmPinRDMA MR 固定页稳定高值正常；斜率才关键

task_exec 根因：失去取消传播的 async generator 链

ray._raylet.execute_streaming_generator_async
└─ DPTaskExecutorActor.chat_completion
   └─ do_chat_completion
      └─ stream_chat_completion
         └─ XDS chat_completion_stream_generator
            └─ vLLM chat_completion_stream_generator
               └─ ReasoningTokensCollector.wrap_result_generator
                  └─ AsyncLLM.generate
                     └─ RequestOutputCollector.get → ready.wait / q.get
客户端断连、abort 或上游重试后，消费端停止拉取但没有关闭内层生成器；引擎侧请求已经终结，却未向旧 collector 投递终态。 Ray 流式链顶仍持有九层生成器帧，request context、detokenizer 全量文本/token、reasoning recorder 与句柄一起常驻。
代码层缺口
RequestOutputCollector.get()等待无终态、无超时
XDSAsyncLLM.generate()旧看门狗只覆盖首 token 前；调用方不关闭就不执行 abort
stream_pipeline.py / task executor包装层缺少 finally → await inner_gen.aclose()
JE / 前端放弃消费路径断连、超时、重试、pod 重建未保证 abort_task(request_id) 到达

修复三件套

  1. 终态完整：引擎正常、异常、KV 拉取失败或丢弃请求时，都向 collector 投递终态/异常。
  2. 级联关闭：所有流式包装层在 finally 中 aclose() 内层，并让放弃消费路径显式 abort。
  3. 独立兜底：generate/get 加最长存活/失速看门狗，actor 周期扫描超龄链；同步限制/清空 reasoning recorder 的全量 token。

上线验证（2026-09-11 15:26）

  • 容器内已确认 stream_stall_timeout_seconds 与 task executor 级联 aclose。
  • prefill 34 分钟触发 544 次 120s 看门狗，约 16 条/分钟；僵死链生命期被钉在 120s。
  • 4 个 decode task_exec 30 分钟斜率约 −49～+2 MiB/h，已走平。

分层判定决策流

working set / usage 上涨→ 拆 anon / file / shmem→ file 为主 → 页缓存，不定性泄漏
anon 上涨→ 拆到 side / role / PID→ 最近两个完整 30 分钟窗口均 >50 MiB/h
VmPin >1 MiB/h → RDMA MR· 线程/fd >5/h → 资源句柄· 显存稳态后仍涨 → GPU 路径
先确认哪层在涨，再决定工具。单点、单窗口、总 RSS、working set 与 nvidia-smi 95% 都不能单独作为泄漏结论。
