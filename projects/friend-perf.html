测试方法（每轮）：对勾选的提供商逐个串行测试，每家发送一条流式 chat/completions 请求（stream=true，max_tokens=输出长度）—— 提示词 ≈ 配置的「输入长度」，其中「缓存命中率」% 为跨轮不变的固定前缀（触发厂商 prompt 缓存）、其余部分每轮随机； 所有请求统一经工作台服务端中转（/api/worktable/llm），各家同一出口、无浏览器 CORS 与本机网络差异，横向可比；超过「单次超时」判失败。 对比图取每家最近 3 个成功样本均值，分桶统计按「输入长度 × 设定缓存命中率」分组；定时模式按「测试间隔」分钟自动循环（依赖页面保持打开）。

指标口径（各图表标题与表头悬停 ⓘ 也可查看）：
· TTFT（首 token 延迟）= 发出请求 → 收到首个流式内容 chunk 的耗时；
· TPOT（每 token 耗时）=（流结束时间 − 首 chunk 时间）÷（输出tokens − 1），输出 tokens 优先取 usage.completion_tokens，未回传按返回文本估算；
· 缓存命中（真实）= 厂商 usage 回传的 cached_tokens（DeepSeek 风格为 prompt_cache_hit_tokens），命中率 = cached ÷ prompt_tokens，不回传的厂商显示 —；
· 输入/输出 tokens 以 usage 回传为准，未回传时输入显示 ~配置目标值（估算）；
· 概览对比取每家最近 3 个成功样本的均值；所有请求统一经服务端中转（早期直连记录标「·直连」）。
