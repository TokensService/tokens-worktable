节点环境

节点环境仅 admin 用户可配置（新增 / 编辑 / 复制 / 删除 / 统一凭证），您为只读查看。

名称SSH 地址内网IPLLM服务地址用户名密码设备状态预留操作

主控「环境」按此列表选择目标节点（可多选，也可一个不选——不选即按无目标节点运行）；SSH 地址可填「IP:端口」。若 SSH 入口与 Kubernetes 节点不同，「内网IP」填写对应的 Kubernetes 节点 InternalIP；运行时自动生成 TARGET_NODE_IP_MAP（SSH 地址 → 内网 IP），渲染、打标签与 NodePort 调用使用内网 IP，SSH/设备查询仍使用 SSH 地址。「LLM服务地址」可选填该节点上 LLM 服务的 IP:端口号（如 192.168.31.175:8000），运行时自动生成 TARGET_LLM_ADDR_MAP（SSH 地址 → LLM 服务地址）注入执行脚本。执行脚本同时注入 TARGET_IP/TARGET_IPS/TARGET_HOSTS、镜像和流水线信息；主控「权重路径」非空时注入 MODEL_PATH，另注入 PIPELINE_PRESETS（本次运行勾选的预设任务 key，JSON 数组，如 ["cleanup","profiling"]）；脚本显式配置的同名参数优先。「预留」列的节点预留分配数据保存在服务端独立存储，不随「导入导出」的配置文件传递。

代码仓

名称URL用户名访问令牌分支获取部署策略操作

主控「代码仓」从此列表选择目标仓库；执行脚本时自动注入环境变量：GIT_URL（仓库地址）、GIT_BRANCH（主控填写的分支）、GIT_USER/GIT_PASSWORD（访问令牌）；脚本显式配置的同名参数优先。分支获取选 Jenkins（浏览器直连/服务端代连）时仓库 URL 可留空，分支取自 Jenkins 多分支任务子任务名。代码仓「部署策略」有两种来源（策略·URL / 策略·脚本）：URL 按分支（{branch} 占位）从接口拉取分页 JSON；脚本则执行 scripts 目录中的脚本（注入 GIT_BRANCH/GIT_URL/GIT_USER/GIT_PASSWORD，stdout 每行输出一个策略名）。配置后主控选择分支即可下拉选择该分支支持的部署策略，运行时额外注入 DEPLOY_STRATEGY（脚本显式配置的同名参数优先）。

环境清理脚本

脚本 勾选主控「预设任务」中的「环境清理」后，流水线运行到其编排位置时执行该脚本（失败不阻断），同样注入 TARGET_*/IMAGE_*/PIPELINE_NAME 与归档相关 ARCHIVE_DIR/ARCHIVE_FOLDER/ARCHIVE_PIPELINE/ARCHIVE_TAG 环境变量。

环境检查脚本

脚本 勾选主控「预设任务」中的「环境检查」后，流水线运行到其编排位置时执行该脚本：检查不通过（脚本非零退出）则阻断后续阶段；同样注入 TARGET_*/IMAGE_*/PIPELINE_NAME 与归档相关 ARCHIVE_DIR/ARCHIVE_FOLDER/ARCHIVE_PIPELINE/ARCHIVE_TAG 环境变量。

Profiling 脚本

脚本 勾选主控「预设任务」中的「Profiling」后，流水线运行到其编排位置时执行该脚本（默认放在流水线的最后，失败不阻断），同样注入 TARGET_*/IMAGE_*/PIPELINE_NAME 与归档相关 ARCHIVE_DIR/ARCHIVE_FOLDER/ARCHIVE_PIPELINE/ARCHIVE_TAG 环境变量。

预设任务设置

系统预设任务（环境清理/环境检查/Profiling）固定内置；此处可添加自定义预设任务：与系统预设一样由主控「预设任务」勾选启用、在流水线编辑中调整执行顺序、运行到编排位置时执行脚本，同样注入 TARGET_*/IMAGE_*/PIPELINE_NAME 与归档相关 ARCHIVE_DIR/ARCHIVE_FOLDER/ARCHIVE_PIPELINE/ARCHIVE_TAG 环境变量；仅页面运行支持，不进服务端定时计划。

脚本目录

流水线阶段、环境清理/检查/Profiling、归档、部署策略与普罗收集脚本都按名称从此目录选用。默认路径为插件安装后的 scripts 目录（随安装位置自动解析，升级插件后跟随新安装位置）；自定义后随设置持久化到服务端（worktable-pipeline.json）并跨浏览器同步，「导出设置」文件同样携带；定时任务与 API 触发的服务端执行使用同一份配置，未配置时服务端也按安装默认路径兜底。

归档配置

每个任务的回显即时归档为独立日志文件 run-<tag>-NN-任务名.log（NN 为 01 起的阶段序号，00 为预设任务：系统预设 + 自定义预设），运行结束再写汇总 run-<tag>.log 与 profiling JSON；均按「流水线名称_年月日时分秒」文件夹归档到此目录（每次运行独立目录）；留空则保底写到 scripts 同级 runs/（不执行归档脚本）。
归档写入日志/profiling 后执行该脚本收集日志；默认 scripts/collect_logs.sh（脚本不存在则跳过）。同样注入 TARGET_*/IMAGE_*/PIPELINE_NAME 与 ARCHIVE_DIR/ARCHIVE_FOLDER/ARCHIVE_LOG_FILE，失败不影响运行；其中归档脚本收到的 ARCHIVE_DIR=归档根目录（host 节点环境日志写到根目录，跨运行共享，不占单次运行目录）、ARCHIVE_FOLDER=本次运行归档文件夹。运行启动时即按「流水线名称_年月日时分秒」生成归档文件夹（每次运行独立目录），并把 ARCHIVE_DIR/ARCHIVE_FOLDER/ARCHIVE_PIPELINE/ARCHIVE_TAG 注入到流水线每个任务（脚本阶段、HTTP/EvalTokens 阶段、清理脚本；任务内 ARCHIVE_DIR 仍=本次运行归档文件夹），脚本显式参数优先。

分析配置 运行历史标题行与阶段详情「🔍 AI 分析」按钮的提示词模板

在「运行历史」勾选一条记录可做单次分析，按勾选顺序选择两条可做 A/B 对比（最多两条）；未勾选时仍使用当前点击回放行。点标题行的 🔍 AI 日志分析 / 📈 Profiling 分析 / ⚡ 性能诊断 按钮会打开侧边会话框，并在本项目设置的工作区中新建 AI 会话；项目尚未设置工作区时会先弹出工作区选择，选定后继续创建。对应提示词包含归档文件绝对路径，只填入输入框，确认无误后手动发送。阶段详情「日志文件」行的「🔍 AI 分析」对该次运行的当前阶段发起分析，用「阶段日志分析」模板，提示词含本阶段归档日志文件路径。 模板占位符：{no} {pipeline} {env} {by} {commit} {status} {dur} {time} {tag} {summary}（单行运行摘要）{archive}（归档文件夹）{logFile} {profileFile}（归档内日志 / profiling 文件，未配置归档时为「（未归档）」）；「阶段日志分析」额外可用 {stage}（阶段名）{stageLogFile}（本阶段归档日志文件，无归档时为「（未归档）」）。

Jenkins 服务配置 连接模式 + 测试连接

「本地浏览器连接」：浏览器直接用 JS 连接 Jenkins（不走桥接）；需 Jenkins 允许跨域（CORS）或与本页同源，否则浏览器会拦截跨域请求。 「远程服务器端连接」：由 DSH 服务端（运行 DSH 的机器）经 /api/worktable/proxy 代连 Jenkins，浏览器不直连；仅允许回环 / 内网地址。

EvalTokens 服务配置 评估任务管理服务 · 连接模式 + Bearer 令牌 + 测试连接 + 获取任务列表

EvalTokens 提供评估任务管理 API（GET /api/open/v1/tasks，请求头需携带 Authorization: Bearer <令牌>），用于查询评估 / 测试任务列表。 「本地浏览器连接」：浏览器直接请求服务 API（需服务允许跨域 CORS 或与本页同源，否则跨域请求被拦截）。 「远程服务器端连接」：由 DSH 服务端经 /api/worktable/proxy 代连服务，浏览器不直连；仅允许回环 / 内网地址（公网地址请用本地浏览器连接）。
