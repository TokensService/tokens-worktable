拉取组织 TokensService 下所有仓库的 Pull Request，点击「AI 检视」即新建 AI 聊天会话并送入评审提示。

构建发行 选择仓库与分支，一键串行：编译构建 → 创建 Tag → 创建 GitCode 发行版 → 上传构建产物附件（可选）；仓库/分支/脚本选择自动缓存本机，刷新不丢失

发行说明

流程：① 服务端经 /api/worktable/exec 执行自动生成的包装脚本：浅克隆所选分支后在仓库根目录运行所选仓内脚本（注入 GIT_URL/GIT_BRANCH/GIT_AUTH_URL/RELEASE_TAG/RELEASE_NAME/BUILD_CMD 及设置页「附加环境变量」；设置页配置「构建容器」时把克隆目录挂载进容器经 docker run 执行，脚本留空则跳过）；配置「产物路径」时构建后按通配收集产物文件到服务端暂存目录 → ② 调 GitCode API 基于分支创建 Tag（API 不可用时自动改用临时脚本浅克隆 git tag 推送，远端已有同名 Tag 拒绝覆盖）→ ③ 调 GitCode API 基于该 Tag 创建发行版 → ④ 把暂存产物经 GitCode upload_url 接口换取 OBS 上传地址后 PUT 直传为发行版附件（未配置产物路径则跳过，上传后清理暂存目录）。认证沿用本页令牌与认证方式。

发行步骤 每步输出可就地展开「回显」查看；总日志在下方统一滚动

构建历史 每次发行归档依赖信息（仓库/分支/脚本/容器/产物路径）、收集到的产物清单与逐步回显日志，存于本机浏览器 localStorage，最多保留 30 条

构建容器（构建运行环境）

「编译发行」构建阶段默认在服务端本机执行：浅克隆所选分支后在仓库根目录运行所选仓内脚本；填写镜像后，克隆目录将挂载到该容器 /mnt/repo 并经 docker run 在容器内执行（GIT_URL/GIT_AUTH_URL/GIT_BRANCH/RELEASE_TAG/RELEASE_NAME/BUILD_CMD 透传进容器）。留空=本机直接执行。容器执行时自动加 --entrypoint bash 覆盖镜像入口（避免 vllm-openai 等镜像把 bash/脚本名当成入口命令 vllm serve 的参数）。
「附加环境变量」按 KEY=VALUE 空格分隔填写：本机执行时直接注入、容器执行时经 -e KEY 透传（如代理、镜像源、特性开关等仓内脚本需要的变量）。
